# Everust v0.1 Scope

## Core Goal
Provide a complete, end-to-end slice answering:
> **"Why did my async Rust service stall or experience lock starvation?"**

## In Scope for v0.1
1. **Canonical Event Set:**
   - `TaskSpawn`: Task initialization with optional name and ID.
   - `TaskWake`: Task notified and ready to be scheduled.
   - `TaskPoll`: Polling duration (elapsed ns) on worker thread.
   - `TaskComplete`: Task completion and total lifetime.
   - `LockWait`: Attempted acquisition of a contested lock.
   - `LockAcquire`: Successful lock acquisition with wait duration.
   - `BlockingOperation`: Synchronous operation on worker thread.
2. **In-Memory Rolling Recorder:**
   - Circular buffer with configurable capacity (default 50,000 events).
   - Snapshot export to `.evr` file.
3. **Deterministic Incident Analyzer:**
   - Rules: Long Task Poll, Mutex Contention, Task Starvation.
   - Formatted text & structured findings output.
4. **Reproducible Workload:**
   - `workloads/lock-contention`: Multi-threaded mutex competition creating measurable contention and starvation.
5. **Interactive Investigation Workbench (`web/`):**
   - Web interface under `/workbench` visualizing recorded flight events, timeline traces, and analyzer findings.
6. **CLI Scaffold:**
   - `inspect` and `demo` commands.

## Out of Scope for v0.1 (Strict Boundaries)
- **No eBPF kernel hooks:** eBPF / kprobes / uprobes will be introduced in v0.2+.
- **No Distributed Tracing / Cloud Backend:** No OpenTelemetry collector, Kafka, Kubernetes, or cloud telemetry backends.
- **No Databases:** Recordings are self-contained `.evr` files.
- **No AI / LLM Diagnostic Summarizers:** Diagnostics must be deterministic, reproducible, and verifiable.
- **No Premature Binary Micro-optimizations:** Prioritize inspectable, robust `.evr` serialization with clean versioning.
